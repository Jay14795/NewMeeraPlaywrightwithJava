# Meera Playwright Java

End-to-end UI automation for **Meera.ai**, converted from the original
TypeScript/JavaScript Playwright project to **Java + Playwright + TestNG**,
built with **Maven** and driven by **Excel** test data (Apache POI).

---

## Requirements

- **Java 17+** (JDK). Tested against JDK 21.
- **Maven 3.9+**
- Windows is required only for the **Test & Train (voice)** module, which uses
  the Windows SAPI text-to-speech engine and the VB-CABLE virtual audio device
  (same as the original). Every other module runs on any OS.

## First-time setup

Install the Playwright browsers once (Chromium etc.):

```bash
mvn -Pinstall-browsers test-compile
```

(That profile runs `com.microsoft.playwright.CLI install`. You can also run
`mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args=install`.)

## Running the tests

Run the whole suite (the login setup runs first and creates the stored session):

```bash
mvn test
```

Run a single module (each of these runs the auth setup first, then the module):

```bash
mvn test -DsuiteXmlFile=suites/campaign.xml
mvn test -DsuiteXmlFile=suites/editCampaign.xml
mvn test -DsuiteXmlFile=suites/duplicateCampaign.xml
mvn test -DsuiteXmlFile=suites/uploadCampaignLeads.xml
mvn test -DsuiteXmlFile=suites/stateCompliance.xml
mvn test -DsuiteXmlFile=suites/addAssistant.xml
mvn test -DsuiteXmlFile=suites/editAssistant.xml
mvn test -DsuiteXmlFile=suites/deleteAssistant.xml
mvn test -DsuiteXmlFile=suites/testandtrain.xml
mvn test -DsuiteXmlFile=suites/login.xml     # no auth needed
```

Authenticated test classes also validate `playwright/.auth/auth.json` in their
shared setup. If the file is missing or the stored session is rejected, the
test clears the browser session, logs in again, and saves a fresh state. This
means an individual authenticated class can also be run directly:

```bash
mvn test -Dtest=CreateCampaignTests
```

## How the conversion maps to the original

| TypeScript / JavaScript                         | Java                                                            |
|-------------------------------------------------|-----------------------------------------------------------------|
| `playwright.config.ts` (projects, timeouts)     | `Config.java`, `BaseTest`, `testng.xml` + `suites/`             |
| `page` fixture (auto browser/context per test)  | `BaseTest` `@BeforeMethod`/`@AfterMethod`                       |
| `storageState` + `dependencies: ["setup"]`      | `AuthenticatedTest` loads `auth.json`; setup runs first in the suite |
| `utils/data-utils.js` (`xlsx` `sheet_to_json`)  | `ExcelDataReader` (Apache POI) → `List<Map<String,String>>`    |
| `for (const data of getTestData(...))`          | TestNG `@DataProvider` + `@Test(dataProvider=...)`             |
| `utils/voice-agent.js` (`execSync` PowerShell)  | `VoiceAgent` (`ProcessBuilder` + PowerShell `-EncodedCommand`)  |
| `expect(...).toBeVisible({timeout})`            | `assertThat(...).isVisible(new ...IsVisibleOptions().setTimeout())` |
| `page.on("dialog"/"close"/...)`                 | `attachPageEventLoggers(page)` in `BaseTest`                    |

### Browser options (from `playwright.config.ts`)

Headed Chromium, launched with `--start-maximized` and **no viewport**
(`setViewportSize(null)`) so the maximized window size is used — identical to
the original `firefoxConfig` object (which, despite its name, launched Chromium).
The assertion timeout is set globally to 40s; per-test timeouts match the
original (300s default, 600s/300s/180s for the voice tests).

## Notes

- `test-data/*.xlsx` and `playwright/.auth/auth.json` were copied over as-is.
  The setup test refreshes `auth.json`; if it is missing or expired it logs in
  again using the first valid row of `login-data.xlsx`.
- The **Test & Train** module needs the Windows SAPI voice + VB-CABLE loopback,
  exactly as the original did. On non-Windows machines those tests will report
  the voice engine is unavailable and TTS will not route to the mic.
- The suite targets the UAT environment (`web-uat04.services.meera.ai`),
  centralised in `Config.java`.
